# Database Design Proposal (PostgreSQL + Prisma)

> **Notice:** This document is an architectural proposal for review during Requirement Discovery. No changes are applied to `prisma/schema.prisma` until Discovery sign-off.

---

## 1. Architectural Principles

1. **Relational Integrity & Foreign Keys:** Strict foreign key constraints guarantee referential integrity across users, transactions, bookings, and audit histories. Cascading rules are set defensively (`Restrict` on financial records, `Cascade` on child audit history logs).
2. **Deterministic Financial Precision:** All monetary amounts use PostgreSQL `DECIMAL(12, 2)` to eliminate floating-point arithmetic errors. Signed amounts reflect refunds natively (negative values).
3. **Auditing & Event Sourcing Lite:** State transitions on transactions and bookings are accompanied by append-only history tables (`TransactionStatusHistory`, `BookingLog`).
4. **Targeted Indexing:** Indexes are strictly added only where query access patterns, composite filters, foreign key joins, or unique lookups demand them, avoiding unneeded write penalties.
5. **Regulatory Soft Deletion:** Soft deletion (`deletedAt`) is applied exclusively to `User`. Financial transactions and bookings are **never hard-deleted or soft-deleted**; their states transition via explicit statuses (`REFUNDED`, `CANCELLED`) to preserve immutable accounting trails.

## 2. Entity Specifications

### 2.1. `Admin` Table
Manages dashboard administrators and authorization credentials.

```prisma
model Admin {
  id               String      @id @default(uuid()) @db.Uuid
  name             String      @db.VarChar(100)
  email            String      @unique @db.VarChar(255)
  passwordHash     String      @db.VarChar(255)
  role             AdminRole   @default(ADMIN)
  avatarUrl        String?     @db.VarChar(500)
  phone            String?     @db.VarChar(50)
  timezone         String?     @default("PST (UTC-08:00)") @db.VarChar(50)
  twoFactorEnabled Boolean     @default(true)
  createdAt        DateTime    @default(now())
  updatedAt        DateTime    @updatedAt

  @@map("admins")
}
```

- **Primary Key:** `id` (UUIDv4).
- **Unique Constraints:** `email` (login identifier).
- **Index:** `email` index automatically generated by `@unique`.

### 2.2. `User` Table
Customer identity, profile attributes, and security status.

```prisma
model User {
  id               String       @id @default(uuid()) @db.Uuid
  userCode         String       @unique @db.VarChar(20)
  firstName        String       @db.VarChar(100)
  lastName         String       @db.VarChar(100)
  email            String       @unique @db.VarChar(255)
  phone            String       @db.VarChar(50)
  dateOfBirth      DateTime?    @db.Date
  addressLine      String?      @db.VarChar(255)
  city             String?      @db.VarChar(100)
  state            String?      @db.VarChar(100)
  country          String?      @db.VarChar(100)
  avatarUrl        String?      @db.VarChar(500)
  role             UserRole     @default(VIEWER)
  status           UserStatus   @default(ACTIVE)
  twoFactorEnabled Boolean      @default(false)
  lastLoginAt      DateTime?
  joinedAt         DateTime     @default(now())
  createdAt        DateTime     @default(now())
  updatedAt        DateTime     @updatedAt
  deletedAt        DateTime?

  transactions     Transaction[]
  bookings         Booking[]
  activities       ActivityLog[]

  @@index([deletedAt, status, role])
  @@index([deletedAt, createdAt(sort: Desc)])
  @@index([deletedAt, firstName, lastName])
  @@map("users")
}
```

- **Primary Key:** `id` (UUIDv4).
- **Unique Constraints:**
  - `userCode` (e.g. `USR-0001` lookup in `/users/:code`).
  - `email` (prevents duplicate customer registration).
- **Index Rationale:**
  - `@@index([deletedAt, status, role])`: Filters on active users by role and status in directory queries.
  - `@@index([deletedAt, createdAt(sort: Desc)])`: Default sorting for paginated user directory.
  - `@@index([deletedAt, firstName, lastName])`: Acceleration for customer name search queries.

### 2.3. `Transaction` Table
Financial ledger entries covering payments, refunds, and transfers.

```prisma
model Transaction {
  id            String            @id @default(uuid()) @db.Uuid
  txnCode       String            @unique @db.VarChar(30)
  reference     String            @unique @db.VarChar(50)
  userId        String            @db.Uuid
  type          TransactionType   @default(PAYMENT)
  status        TransactionStatus @default(PENDING)
  amount        Decimal           @db.Decimal(12, 2)
  currency      String            @default("USD") @db.VarChar(3)
  productName   String            @db.VarChar(255)
  paymentMethod String            @db.VarChar(100)
  gatewayFee    Decimal           @default(0.00) @db.Decimal(12, 2)
  subtotal      Decimal           @db.Decimal(12, 2)
  total         Decimal           @db.Decimal(12, 2)
  settledAt     DateTime?
  createdAt     DateTime          @default(now())
  updatedAt     DateTime          @updatedAt

  user          User              @relation(fields: [userId], references: [id], onDelete: Restrict)
  statusHistory TransactionStatusHistory[]

  @@index([userId, createdAt(sort: Desc)])
  @@index([status, createdAt(sort: Desc)])
  @@index([type, status])
  @@index([createdAt(sort: Desc)])
  @@map("transactions")
}
```

- **Primary Key:** `id` (UUIDv4).
- **Unique Constraints:**
  - `txnCode` (e.g. `TXN-0017`).
  - `reference` (gateway reference string e.g. `ref_992743055`).
- **Foreign Key:** `userId -> User.id` with `onDelete: Restrict` (prevents deleting a user with financial transactions).
- **Index Rationale:**
  - `@@index([userId, createdAt(sort: Desc)])`: Supports "Related Customer Ledger Entries" and user detail "Recent Transactions".
  - `@@index([status, createdAt(sort: Desc)])`: Speeds up dashboard aggregations (MoM revenue, pending transactions, recent transactions table).
  - `@@index([type, status])`: Accelerates filtered searches on `/transactions`.
  - `@@index([createdAt(sort: Desc)])`: Default chronological sorting on `/transactions`.

### 2.4. `TransactionStatusHistory` Table
Immutable audit trail for transaction lifecycle milestones.

```prisma
model TransactionStatusHistory {
  id            String            @id @default(uuid()) @db.Uuid
  transactionId String            @db.Uuid
  status        TransactionStatus
  note          String            @db.VarChar(500)
  createdAt     DateTime          @default(now())

  transaction   Transaction       @relation(fields: [transactionId], references: [id], onDelete: Cascade)

  @@index([transactionId, createdAt(sort: Asc)])
  @@map("transaction_status_histories")
}
```

- **Primary Key:** `id` (UUIDv4).
- **Foreign Key:** `transactionId -> Transaction.id` with `onDelete: Cascade`.
- **Index Rationale:**
  - `@@index([transactionId, createdAt(sort: Asc)])`: Loads the step-by-step "Processing History" timeline in chronological order.

### 2.5. `Booking` Table
Service bookings and consultation meetings.

```prisma
model Booking {
  id            String        @id @default(uuid()) @db.Uuid
  bookingCode   String        @unique @db.VarChar(30)
  userId        String        @db.Uuid
  serviceName   String        @db.VarChar(255)
  category      String        @db.VarChar(100)
  scheduledAt   DateTime
  durationHours Decimal       @default(1.50) @db.Decimal(4, 2)
  endTime       DateTime
  location      String        @default("Virtual - Zoom Link Provided") @db.VarChar(255)
  customerNotes String?       @db.Text
  status        BookingStatus @default(PENDING)
  amount        Decimal       @db.Decimal(12, 2)
  paymentStatus PaymentStatus @default(PENDING)
  paymentMethod String        @db.VarChar(100)
  invoiceCode   String        @unique @db.VarChar(30)
  createdAt     DateTime      @default(now())
  updatedAt     DateTime      @updatedAt

  user          User          @relation(fields: [userId], references: [id], onDelete: Restrict)
  lifecycleLogs BookingLog[]

  @@index([userId, scheduledAt(sort: Desc)])
  @@index([status, scheduledAt(sort: Asc)])
  @@index([category, scheduledAt])
  @@index([scheduledAt(sort: Asc)])
  @@map("bookings")
}
```

- **Primary Key:** `id` (UUIDv4).
- **Unique Constraints:**
  - `bookingCode` (e.g. `BKG-0045`).
  - `invoiceCode` (e.g. `INV-98943`).
- **Foreign Key:** `userId -> User.id` with `onDelete: Restrict`.
- **Index Rationale:**
  - `@@index([userId, scheduledAt(sort: Desc)])`: User detail "Recent Bookings" and total completed bookings count.
  - `@@index([status, scheduledAt(sort: Asc)])`: "Active Bookings" filter and upcoming appointments view.
  - `@@index([category, scheduledAt])`: Powers dashboard "Bookings by Category" chart aggregation.
  - `@@index([scheduledAt(sort: Asc)])`: Default chronological sorting on `/bookings`.

### 2.6. `BookingLog` Table
Immutable lifecycle audit log for bookings.

```prisma
model BookingLog {
  id          String   @id @default(uuid()) @db.Uuid
  bookingId   String   @db.Uuid
  event       String   @db.VarChar(100)
  description String   @db.VarChar(500)
  createdAt   DateTime @default(now())

  booking     Booking  @relation(fields: [bookingId], references: [id], onDelete: Cascade)

  @@index([bookingId, createdAt(sort: Asc)])
  @@map("booking_logs")
}
```

- **Primary Key:** `id` (UUIDv4).
- **Foreign Key:** `bookingId -> Booking.id` with `onDelete: Cascade`.
- **Index Rationale:**
  - `@@index([bookingId, createdAt(sort: Asc)])`: Renders the "Booking Lifecycle Logs" timeline on booking details.

### 2.7. `ActivityLog` Table
Security and account audit events for customer profiles.

```prisma
model ActivityLog {
  id          String   @id @default(uuid()) @db.Uuid
  userId      String   @db.Uuid
  action      String   @db.VarChar(100)
  description String   @db.VarChar(500)
  createdAt   DateTime @default(now())

  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId, createdAt(sort: Desc)])
  @@map("activity_logs")
}
```

- **Primary Key:** `id` (UUIDv4).
- **Foreign Key:** `userId -> User.id` with `onDelete: Cascade`.
- **Index Rationale:**
  - `@@index([userId, createdAt(sort: Desc)])`: Renders the user detail "Recent Activity" vertical feed.

---

### 2.8. `Alert` Table
System operational notifications displayed on the dashboard.

```prisma
model Alert {
  id          String        @id @default(uuid()) @db.Uuid
  title       String        @db.VarChar(255)
  description String        @db.VarChar(500)
  severity    AlertSeverity @default(INFO)
  isResolved  Boolean       @default(false)
  createdAt   DateTime      @default(now())

  @@index([isResolved, createdAt(sort: Desc)])
  @@map("alerts")
}
```

- **Primary Key:** `id` (UUIDv4).
- **Index Rationale:**
  - `@@index([isResolved, createdAt(sort: Desc)])`: Pulls unresolved alerts quickly for the dashboard widget.
